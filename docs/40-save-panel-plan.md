# 保存面板：方案论证（v3 设计稿 × 现有后端）

> 本文回答三个问题：**v3 设计稿到底要什么**、**后端已经有什么/缺什么**、**按什么顺序做、每步怎么验**。
> 只做论证，不含实现。所有现状结论都带 `文件:行`；设计稿里没有的东西不臆造。
> 标注：`[已有]` 可直接用 · `[缺]` 不存在 · `[需改]` 存在但要动 · `[待定]` 需人拍板。

---

## 0. 结论摘要

1. **后端已经把这套东西的"核心三个件"做完了**：格式能力与限制 `[已有]`、偏好结构 `[已有]`、PNG 母版 → 目标格式的转码 `[已有]`；缺的是**把它们接起来的那一层**和一个面板。
2. **最大的缺口不是 UI，而是"没人能到达偏好"**：`SavePreferences` 有序列化、有默认值、有滚动前置检查在消费它，但**设置窗口里没有任何格式/质量控件**，转码函数 **`convert()` 也一个生产调用者都没有** `[缺]`。
3. **v3 比"保存面板"大得多**：它是一张 **920×569 dip 的模态对话框**（`docs/design/save-panel-demo-v3.html:41`、`:457`），含预览对比、缩放、体积上限、尺寸缩放、长图分割、PDF、每格式高级选项 `[待定：是否全要]`。
4. **建议先做"能保存且能选格式"的最小闭环**（6 个阶段，见 §5），把预览/体积上限/缩放/分割留后；**唯一必须先答的设计问题**是模态对话框还是面板内嵌（§4.6）。

## 1. 需求与边界

### 1.1 这一版要做的

- **保存到文件**：选定目录、文件名、格式，写出一个文件，并把它记进历史 `[v3 有，代码无]`；
- **格式**：PNG / JPG / WebP（WebP 无损）`[后端已有]`；
- **质量**：JPG 的质量 `[后端已有]`（UI 语义待定，§4.5）；
- **同名处理**：重命名（默认）/ 覆盖 `[v3 有]`；
- **页面上的"保存"去向**：面板现在只有 复制/贴图 两段 `[已有]`，要加第三段 `[缺]`；
- **失败要说实话**：磁盘满 / 无写权限 / 格式超限，都要落到具体字段或具体错误 `[需改]`。

### 1.2 这一版**不做**（明确划掉）

| 不做 | 理由 |
| --- | --- |
| 预览区"编码后"的真实编码与体积预估 `[划掉]` | v3 用 canvas `toBlob` 实测（`v3:1331`、`:1337`），后端没有"只编码不写盘"的服务；而且它的文案自己承认"体积为实测，选项按系数修正"（`v3:1505`）—— 这套模型要单独立项 |
| 体积上限 + 自动缩小尺寸 `[划掉]` | 依赖上一行 |
| 尺寸缩放（数值/百分比/锁比）`[划掉]` | 需要重采样器，后端没有；且捕获流程已有"物理像素"语义，缩放是新的产品决定 |
| 长图分割（✂）+ PDF 输出 `[划掉]` | 新的输出形态：多文件与 PDF 写作者；`isLong()` 的阈值（3000 px 且 ≥2.5）是设计稿 arbitrariness，未论证 |
| 每格式高级选项（PNG 量化 / WebP 档位）`[划掉]` | 与"WebP 只做无损"的既有决定冲突（`save_format.rs:145` 的 label 就是 `WebP（无损）`） |
| 对比滑块 / 棋盘格 / 缩放查看器 `[划掉]` | 需要一套图像查看器；v1 用"一个缩略图"就够（§5 阶段 4） |

### 2.3 保存时的状态机（从 `v3:969-991` 读出）

```
点"保存"
  ├─ 计算 sliceHeights() / isMulti()      ← 分割（划掉，但状态机里有）
  ├─ targetPath() 解决冲突 → 记 EXISTING
  ├─ 若文件名含 [序号] ⇒ seq++ 并持久化
  ├─ 后置动作：复制路径 / 打开文件夹
  ├─ pulseSave()                          ← 按钮脉冲反馈
  └─ showToast({ title: 已保存/已覆盖/已保存为 X,
                 sub: 路径 · 体积 · 尺寸,
                 actions: [撤销 · 重命名 · 在历史中查看 · 打开文件夹] })
```

**每个字段的"错误/warn"是同一条通道**：`renderMsg` + `field-msg is-error|is-warn`（`v3:1423-1432`），并带一个**可点动作**（`mkdir` / `fixname` / `trim`）。

### 2.4 设计稿里**不明确或自相矛盾**的地方 ✗

| # | 问题 | 影响 |
| --- | --- | --- |
| 1 | **质量 高/中/低 没有数值定义** ✗ —— 后端的文档写的是"UI 提供 85/92/95"（`save_format.rs:230-234`），v3 却只有三档标签 | 必须定映射，否则"高"是多少没人知道 |
| 2 | **WebP 的质量行与提示互相矛盾** ✗ —— 质量分段器对"除 PNG 外"都显示（`v3:1097`），而提示文案在 WebP 下写的是"WebP 无损模式不支持质量调整"（`v3:1587`），`isLossless()` 又把 WebP 当成**可能有损**（`v3:1305`）。后端只有无损 WebP（`save_format.rs:145`） | 对我们而言 WebP **永远**无损：质量行必须隐藏、提示必须显示 |
| 3 | **尺寸默认就是可编辑的** ✗ —— `w/h` 与 `reset` 一直在（`v3:585-608`），但"保存"这件事本身并不要求缩放 | 缩放要么是 v1 的一部分（要重采样器），要么整块隐藏 |

## 4. 关键决策与取舍

### 4.1 保存时机

- **选项 A**：捕获结束立即按偏好写盘（现状滚动路径的做法）；
- **选项 B**：确认后再写（面板里点"保存"才写），artifact 始终只是历史里的母版。

**推荐 B** ✓，理由：artifact 已经是**无损母版**（`convert.rs:3` 的设计），转码是它下游的一步；写盘失败时母版仍在，用户可重试；而且"保存"能带自己的目录/名字/格式参数，不必污染捕获流程。滚动路径的桌面副本改为"保存规则的默认实例"（§5 阶段 5）。

### 4.2 格式/质量放在哪

面板里选、设置里记"上次用的" ✓：面板写回 `SavePreferences`，下一会话的**滚动前置检查**仍然读它（`preferences.rs:29`）—— 这两个读点本质是同一个语义："下次保存会用什么格式"。

**当前它是死配置** ✗：模型里有、JSON 里有、消费者有，但没有 UI 能改 ⇒ 阶段 1 必须有"能改"的入口，否则面板一开就是永远 PNG。

### 4.3 默认文件名与目录

- 目录：**上次成功保存的目录**，首次用桌面（`SHGetKnownFolderPath(FOLDERID_Desktop)` 已有先例，`scroll.rs:533-541`）；
- 名字：`SnapClip-[日期]`（与 v3 一致，`v3:718`），变量表同 v3（`v3:737-743`），但**`[序号]` 语义先定为"每次保存 +1，全局一个计数器"**，写进设置文件；
- 冲突：**默认重命名**（`SnapClip-2026-10-18 (2).png`），底部给"改为覆盖"。

### 4.4 剪贴板与文件的关系

**正交** ✓：保存不自动复制；"复制图片"仍是独立动作（v3 底部保留，`v3:679`）。理由：现有确认流程是"复制/贴图"二选一（`session.rs:1179`），把"保存"混进去会让"复制"的语义变模糊；而 v3 的 `复制路径` 是**保存之后**的可选动作，与"复制图片"不是一件事。

### 4.5 质量滑杆的语义（JPG / WebP）

- **JPG**：三档 → 数值 **95 / 92 / 85**（沿用 `save_format.rs:230-234` 的 85–95 带，92 是默认 `:260`）；
- **PNG**：不显示质量（无损）；
- **WebP**：**无损，也不显示质量** ✗（v3 目前只对 PNG 隐藏，`v3:638` ⇒ 必须改文案与可见性）；
- 存进 `SavePreferences` 的永远是数值（`quality()` 会夹到 1..=100，`save_format.rs:253`），三档只是 UI。

### 4.6 形态：模态对话框 vs 面板内嵌（**最大的一条**）

| | 模态 920×569（v3） | 面板内嵌（现有 363 dip 高） |
| --- | --- | --- |
| 预览 | 有空间，能放对比滑块 | 只能放一个缩略图 |
| 字段 | 全部放得下（路径/名字/格式/质量/冲突/后置动作） | 要折叠或分页 |
| 与捕获面板的关系 | 结束后再弹一个窗（多一次上下文切换） | 就在原地，Tab 顺序连续 |
| 实现成本 | 新窗口 + 新渲染 + 新焦点管理 | 复用 `RegionPanel` 的命中/焦点/绘制 |
| 风险 | 焦点与 Z 序（面板是 D2D 直接画在浮层上的） | 面板已经 277→363 dip，再加路径+名字+格式≈ +120 dip ⇒ 约 480 dip，可能遮住选区 |

**推荐：模态对话框，但分两步** —— v1（阶段 2）先做**只有表单、没有预览**的模态（约 700×300 dip），阶段 4 再补预览。理由：字段太多，内嵌会把捕获面板撑到遮住选区；而预览是 v1 里唯一可后置的重件。

### 4.7 失败语义

三档，全部往"具体"里落：

| 失败 | 呈现 | 依据 |
| --- | --- | --- |
| 路径为空 / 非法字符 / 保留名 | **字段级** error + 可点修复（替换 `_` / 去尾点） | 同 v3 `validate()`（`v3:1404`） |
| 目录不可写 / 磁盘满 | **保存级** error，保留母版可重试 | 沿用 `Status::Storage` 的先例（`scroll/mod.rs:216` 一带） |
| 格式装不下（WebP > 16383 等） | 选择时**即时**禁用该项并说明上限 | `can_encode`（`save_format.rs:129`）+ 现有 label 已带"无损"说明 |

## 5. 分阶段拆解

> 每阶段独立可交付、可验证；顺序按依赖排。

### 阶段 1：保存服务（无 UI）`[1–2 天]`

- **目标**：给定"目录 + 文件名模板 + 格式 + 质量 + 冲突策略"，把 artifact 转码写出，返回最终路径；失败给人话。
- **涉及**：`apps/snapclip/src/capture/` 新模块（如 `save.rs`）+ 复用 `convert_to_file`（`convert.rs:38`）+ `SavePreferences`（`:253`）。
- **验收**：单测覆盖 3 格式 × 2 冲突策略 × 5 种失败（空路径/非法字符/不可写/磁盘满注入/格式超限）；PNG 保存 = 母版字节拷贝。
- **风险**：低。

### 阶段 2：模态表单（无预览）`[2–3 天]`

- **目标**：路径 / 名字（+变量）/ 格式 / 质量 / 冲突 / 保存·取消；字段级校验与 v3 一致。
- **涉及**：新窗口（`apps/snapclip/src/`）+ `Destination` 不变（此阶段由面板按钮直接打开）。
- **验收**：纯状态单测（校验表逐条）+ L4 渲图（关闭/错误/警告三态）；Tab 顺序与 Enter/Esc。
- **风险**：焦点与 Z 序（浮层是 D2D 直绘）。

### 阶段 3：接进捕获流程 `[1–2 天]`

- **目标**：`Destination` 加 `Save`（`region.rs:355`，`ALL` 三连自动带动几何与 Tab）+ `confirm_action` 分派 + 结束后打开阶段 2 的模态。
- **验收**：确认分派单测（复制/贴图/保存各走各的）；真机一次"F7 → 框选 → 保存"落一个文件。
- **风险**：`Destination::ALL.len()` 驱动几何（`geometry.rs:1439`），宽选区的面板可能变窄——需 L4 渲图确认。

### 阶段 4：预览缩略图 `[1–2 天]`

- **目标**：左侧显示成品缩略图（一张，静态），可选"原图/成品"切换；**不做**体积实测与对比滑块。
- **验收**：缩略图与成品同比例、不拉伸；长图按高度封顶。
- **风险**：低。

### 阶段 5：滚动路径并入同一规则 `[1 天]`

- **目标**：滚动桌面副本改用阶段 1 的服务（目录/模板/格式/冲突），删掉写死的 `SnapClip-{session_id}.png`（`scroll.rs:567`）。
- **验收**：`--scroll` 产物与旧路径**逐像素相同**（同名策略下重命名）、日志格式不变。
- **风险**：滚动路径在 export 线程上，命名冲突需要 IO 前置检查。

### 阶段 6：后置动作与设置项 `[0.5–1 天]`

- **目标**：保存后"复制路径 / 打开文件夹"两枚 chip；设置窗口里给格式/质量一个真正的位置（或明确"只在保存面板里改"）。
- **验收**：chip 状态持久化；设置 JSON 往返。

**总计约 7–11 天**（不含 §1.2 划掉的预览编码/体积上限/缩放/分割/PDF）。
