# 截图浮层：三项文本全关之后，左上角还剩下什么

诊断任务，**未改产品代码**；只加了一条 `#[cfg(test)]` 诊断测试（去留待定，见 §5）。

- 三项全开 ⇒ `size_label_bounds` 为 `Some`（徽标有位置，菜单有锚点）；
- 三项全关 ⇒ `size_label_bounds` 为 **`None`**；
- 并且同一位置（选区左上 `-12` 行、`+12` 列）采样到的是**被遮罩的背景像素**，不是面板底 —— 也就是说这里是**什么都没画** ✗，而**不是画了一个空白圆角块** ✓（这一点很重要：若只是空白 pill，问题就只是"难看"；实际是"不存在"）。

结论：**三项全关 ⇒ 徽标、徽标菜单、以及面板的唯一入口，一起消失**。

## 2. 定性：设计后果 + 一个交互缺陷

**「三项全关 ⇒ 没有徽标」本身是有意的** ✓：代码注释与 `docs/23 §14.54` 都写明，徽标是"尺寸/位置/单位"的书写者，三项都不写就没有它要写的东西。

**但它把"文本的书写者"和"面板的锚点"当成了同一个东西** ✗，于是：

- 面板是**唯一**的确认入口（`开始`、`取消`、去向、延迟、圆角、图片卡都只在面板里）；
- 面板**只**能由徽标打开；
- 徽标**只**在"至少一项文本开着"时才存在；

三条合起来 ⇒ **用户把三项都关掉之后，浮层上就再也点不开面板了** ✗✗：去向选不了、延迟改不了、圆角改不了、`开始`按钮不见了。可恢复 —— **设置窗口里有这三项开关**（`apps/snapclip/src/settings/settings_view.rs:87-88`、`:270`、`:278`，模型在 `settings/model.rs:37-39`）—— 但那是**离开截图、去另一个窗口**才能做到 ✓，而且用户未必知道要去那里 ✓。

所以定性是：**规则本身是设计后果 ✓，规则造成的结果是交互缺陷** ✗ —— 它是一扇**单向门**：把"你要不要显示文字"与"你还能不能开始截图"绑在了一起。

顺带回答任务里的第 4 问：**延迟选择器确实也丢了** ✗，而且比它严重的是 **`开始`/`取消` 与去向选择一起丢了** ✗。

## 3. 三种解法

### A. 浮层始终存在，只隐藏文本行 ✓

- **视觉**：一个**空的圆角底块**留在选区左上角（宽度退到内边距，约 2 × 10 dip）；里面什么都没有。
- **代价**：一处绘制改动（`text.is_empty()` 不再返回 `None`，改成"用最小尺寸定位"）；命中测试自动跟着回来（同一份 bounds）。
- **风险**：**空块本身没有含义** ✗ —— 用户看到的是一个"像是渲染坏了的小方块"✓；而且它遮住选区左上角的一小块 ✗。
- **要改设计稿**：是（`docs/design/overlay-ui-demo.html`）。

### B. 退化为最小徽标（推荐 ✓）

- **视觉**：文本为空时，`尺寸/位置/单位` 三项不写，但**徽标保留为一个小图标**（沿用现有 `panel_icon.rs` 的字形，例如标签/箭头字形）—— 一个 20 dip 见方的圆角块，悬停仍然点亮（`label_hovered` 已有），点击仍开面板。
- **代价**：同上（一处定位 + 一处绘制），多一个"文本为空时画图标"的分支；字形必须**已在字体子集里**（`subfont/drawn-text.txt`），否则会渲染成豆腐 ✗ —— 需要确认或补一个字形。
- **风险**：几乎没有交互风险 ✓；唯一成本是"图标语义"，但悬停高亮 + 点击开面板已经说明了它的用途 ✓。
- **要改设计稿**：是（`overlay-ui-demo.html`）。

### C. 把"开始/取消/去向/延迟"移出浮层，浮层随文本一起消失

- **视觉**：三项全关 ⇒ 浮层上**真的什么都不剩** ✓（符合"我不想看任何文字"的原始意图）。
- **代价**：最大 ✗ —— 要重新设计确认入口（键盘确认？独立工具栏？），且要重新安排延迟/去向/圆角的落点。
- **风险**：改动面大，且与现有 `docs/23 §14.54` 的"徽标即入口"模型冲突 ✗。
- **要改设计稿**：是，而且不止一稿。

## 4. 推荐

**B** ✓。理由：

1. 它**尊重用户的原始意图**（三项全关 = 不要写任何文字 ✓），不像 A 那样留一个无意义的空块 ✗；
2. 它把**根因**修掉 —— "锚点"不再依赖"文本" ✓（`AGENTS.md`：根因优先）✓；
3. 改动小、命中测试与菜单入口自动恢复 ✓；
4. 与现有模型（徽标 = 悬停高亮 + 点击开面板 ✓）一致，`docs/23 §14.54` 只需补一句"文本为空时退化为图标" ✓。

**建议同时加一条约束** ✓：面板的确认入口（`开始`/`取消`/去向）**不应**再依赖任何"显示偏好" ✗ —— 可以在 `input.rs` 的 `toggle_region_panel` 旁加一条断言或测试：**只要处于可确认状态（`Selecting`/`Selected`），`label_badge` 必须为 `Some`** ✓。这条测试能防止将来再出现同类单向门 ✓。
