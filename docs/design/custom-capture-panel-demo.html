demo 和实现的关系

  • 几何与颜色逐项对齐：上表每个数都能在 geometry.rs / d2d.rs 找到同一个来源；CSS 变量名后面就注了常量名。顶栏那行是本页实测（面板 420 × 277、卡 189、比例按钮 64、交换 22、菜单 82、去向轨道 150、延时轨道 142、单位轨道 64、倍率 46、芯片 46、最挤一行不溢出）。
  • 比例按钮的位置变了，槽没变：它还是 PanelSlot::Ratio，只是从独立行搬进尺寸卡头。菜单从「跟着触发器宽」改成「跟着最宽项走」（max-content = 「无比例」文本 + 26 检查位 + 10 右内边距 + 5×2 菜单内边距 = 实测 82），右缘对齐卡片右缘；按钮实测 64，比菜单窄。
  • 交换按钮：新的 PanelSlot::Swap，22×22 与位置卡的居中 / 原点同规格、同悬停语言，放在比例按钮右侧（两卡最右侧都是动作图标，视觉对齐）。
  • Tab 序：卡头在数字之前 ⇒ 顺序变成「比例 → 交换 → 宽 → 高 → X → Y → 去向 → 延时 → 角标 → 单位 → 图片卡头 → …」，共 16 项（原 14 项 + 去向 + 交换）。若想保持「宽 → 高 → 比例 → 交换」，按钮改用绝对定位、DOM 放在数字之后；demo 用的是自然顺序。
  • 场景就是"工作区"：正常场景 700 高，菜单挂得下 ⇒ 挂在卡头下方；点"小工作区"把工作区压到 380 高 ⇒ 下方只剩一小截，按 dropdown_top 的规则翻到上方、并压住面板（这是代码的行为：能选到每一项，但必然遮住点什么）。
  • 插入符：实现是缓冲 + 光标下标、3 px 宽 23 dip 高、500 ms 闪烁、退格只删一个字符；中文输入法的全角数字在 WM_CHAR 那条路上归一化。本页用同一套模型，闪烁用 CSS steps(1) 每 1 s 一闪（半周期 500 ms）。点进数字格后用 ←/→ 把光标移到中间再输入，可验证"不是全选替换"。
  • 平移动画：SEGMENT_SLIDE_MS = 140、缓出；本页 transition: transform 140ms。去向、格式、质量都复用同一个 .seg 语言。
  • 菜单底是 0.92（与面板同一支画刷）⇒ 展开时下面的行会透出约 8%。这不是本页的透明 bug，是代码的画法；拿不透明确认过：底色一改实，透出立刻消失。
  • 字体：实现内嵌 HarmonyOS Sans SC 子集，等宽串走 Consolas 回退；浏览器里没有内嵌字体，本页用系统回退 ⇒ 字宽会有细微差别（29 / 34 / 48 是设备层按真实字体量出来的）。

拟议、尚未在代码里

  • 去向默认 = 复制：与现在 确定 的行为一致（复制 + 入历史），迁移成本为零。
  • 延时与去向统一：代码现在把延时到点写死成贴图（panel-delay-pin）⇒ 将来延时要走同一个去向；"3 秒后复制 / 保存 / 贴图" 都成立，而不是只有贴图。
  • 「保存」暂缺：目录与命名策略没定（要另做保存面板）⇒ demo 保留这一段表达设计意图，但标成"未实现"。代码落地时先只做「复制」「贴图」两段，等保存面板就绪再加 —— 选了没反应的选项比没有更糟。
  • 比例搬进尺寸卡头：语义上更对——比例锁的是宽高比，改宽联动高，本来就是尺寸卡的事；位置卡头有「居中 / 原点」，尺寸卡头现在有「比例 + 交换」，两张卡头对称了。它不是复活 §14.55.10 删掉的那个比例锁图标，而是把独立行的触发器换了位置和形态，文档要按这个说法更新（那句「尺寸卡头部没有图标」要改写为「头部有比例按钮和交换动作」）。
  • 交换的含义：只交换宽高两个数，不做别的。比例非自由时把比例一起翻转，是为了不让「锁 16:9 却显示 9:16 的数」出现；21:9 没有 9:21 对应项，退回「自由」是唯一自洽的选择（也可以考虑在 RATIOS 里补上 9:21，但那会改变菜单项数 = 改动更大，本 demo 没做）。位置不自动夹，越界显示红字——与打字路径一致，不悄悄挪选区。
  • 去向（复制 / 保存 / 贴图）：这是原「比例行」让出来的位置里最值得放的功能——它和图片卡是正交的两个维度（「成图自己的属性」vs「成图去哪」），代码里 --out-* 的注释早就把「去向」留给了复制 / 保存 / 贴图。和延时拼一行也说得通：一个「什么时候截」，一个「截完做什么」，都在流程维度上。
  • 格式只在保存时有效：复制到剪贴板、贴图都是位图，没有格式概念。所以格式 / 质量在非「保存」去向时压暗（和 PNG 时质量压暗同一套语言，轨道不消失、不跳版），摘要与页脚读数也不带格式。这是这个功能的隐性成本，本版已经处理；若不想接受这个分叉，就别做去向。
  • 页脚输出读数：复用页脚那个槽，不加行，面板仍是 277 高。切到 DP 看换算，把宽改到会越界看它如何让位给红字。outputText() 是这条的全部逻辑；图片区关掉时读数里的格式固定为 PNG、没有圆角。放不下时 DP 先去掉 dp 一侧、PX 先去掉「将」，不靠省略号。
  • 为什么叫「去向」而不是「输出」：「输出」留给成图本身的属性（图片卡里的格式 / 质量 / 圆角），「去向」是截完之后做什么。两者不混。
  • 图片区：面板底部常驻一张主色淡染的「图片」卡，收起时只占一行（右侧显示当前设置），点这一行展开成「格式 / 质量」和「圆角」两行；再点收回。收起时设置照样生效，页脚读数也会带上。顶栏「拟议：图片区」整个关掉 = 当前实现（面板 277）。JPG 没有透明通道：带圆角或阴影的窗口截图保存为 JPG 时，透明处要有个垫底色（待定）。

拟议：圆角（滑动条）

  • 含义：输出那张图的四角统一圆角（角外透明），不是只改框的画法。读数里会带 · 圆角 12（恒用 px）。四个角分别设置没有做——要的话得 4 条滑动条或一个「联动」开关，面板会再长。
  • JPG 没有透明通道：圆角 > 0 又选了 JPG 时，四角要有垫底色（待定）；PNG / WebP 直接保留透明。
  • 上限随选区变：短边只有 60 px 时最多 30 px；选区缩小后超限的值按上限显示，放大回来会恢复。
  • 高度：图片区关掉 420 × 277（当前实现）；打开后收起 420 × 329（+52：10 上距 + 42 一行卡），展开 420 × 401，向下长、顶边不动。

不在本 demo 范围

  • 浮层行为：尺寸角标本身、选框与手柄、遮罩/模糊、延时倒计时、贴图 —— 都不是面板的内容，本页只画面板。
  • 完整键序：Tab 顺序（16 项）、方向键在分段器内换段、Esc 关面板，在实现里都有；本页只演示"聚焦态怎么画"，Esc 只用来退出输入、不收面板。
  • IME 组合过程：见上（本页只有 keydown）。
