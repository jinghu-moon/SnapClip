# 52 · F3 剪贴板贴图：内容分类与展示设计

设计初稿：2026-11-02；原型与交互约定更新：2026-11-03。

状态：F3、共享剪贴板能力、图片/文档/文件窗口已实现；生产无头交互与纯规则回归已执行。Windows 热键、来源应用、DPI 与读屏的实机验收尚未完成。§3–§10 保留设计目标，实际交付范围、调整和验证证据见 §11。

交互预览：[剪贴板贴图 HTML Demo](design/clipboard-pin-demo.html)。离线单文件 UI / 交互原型，包含 **28 个预设示例：21 种内容与边界样本、7 种无窗口读取结果**，另有主动粘贴试验区。支持深浅主题、全部对照、背景、透明度、100 / 125 / 150 / 200% 排版缩放模拟与常显工具条开关。

原型重点是展示效果、发现入口、状态切换和反馈。复制、打开、文件拖出、置顶和鼠标穿透均在网页内模拟，不执行系统操作。粘贴仅接收用户本次主动粘贴的 `clipboardData`，不是 Windows 格式读取器；缩放模拟也不能作为真实 DPI 验收结论。

## 1. 目标与基本事实

用户复制内容后按 F3，将**当时系统剪贴板中的内容**固定在桌面上，供对照、阅读、复制或访问。F6 继续消费最近确认的截图选区，二者共享贴图生命周期。

设计从以下事实出发：

1. 一次复制可以同时发布多种格式。文本、HTML、RTF、位图不一定是多份独立内容，而可能是同一对象的不同表示。[W1]
2. 文件引用与文件字节不同。`CF_HDROP` 提供已有文件的位置；复制文件不等于获得了一份永久的文件内容快照。[W2]
3. 图片按像素观看，文档按文字阅读，文件集合按条目访问。三者需要不同的滚动、选择、缩放和打开行为。
4. 剪贴板随后会变化。已创建的贴图必须独立于下一次复制，不实时跟随系统剪贴板。
5. 内容分类必须保留原文与备选表示。识别成链接、代码或表格，不应丢掉用户复制的文字、空格、换行和原始格式。

因此采用 **3 类内容对象 + 文档展示模式 + 文件条目种类**，不为每个后缀或文本特征创建一套窗口宿主。

## 3. 内容分类

### 3.1 一级：用户复制的对象

| 内容对象 | 可靠依据 | 默认展示 | 主要交互 |
| --- | --- | --- | --- |
| 图片 `Image` | 可成功解码的 PNG、DIBV5、DIB、Bitmap 等图片表示，且没有更完整的文档/文件对象 | 图片贴图，保留透明度，原比例显示 | 拖动、缩放、复制图片、关闭；复用现有图片行为 |
| 文档 `Document` | Unicode 文本，或可解析出文字/结构的 HTML、RTF | 根据内容选择下表的文档模式 | 文字选择、复制、滚动、切换原文模式、关闭 |
| 文件集合 `Files` | 明确的文件引用，例如 `CF_HDROP` | 单文件卡片或多文件列表 | 只读清单、按需操作单项、复制文件引用/路径、打开所在位置、关闭 |

空剪贴板、读取失败、只有未知格式属于**读取结果状态**，不是第四种可贴内容。不能创建一个内容为空的“其他”窗口冒充成功。

### 3.2 二级：文档的展示模式

这些模式共享一个文档窗口。只改变正文呈现与相关命令，不创建互斥的数据副本。

| 模式 | 识别条件 | 展示方式 | 必须保留的退路 |
| --- | --- | --- | --- |
| 普通文本 | 默认；没有更可靠的结构 | 左对齐、保留段落与空行、自动换行、正文可选择 | 复制原文；长行可切换不换行 |
| 富文本 | HTML/RTF 能可靠解析出正文与受支持格式 | 原生文字布局，呈现段落、基础强调、列表、链接等；不照搬网页 CSS | 切换纯文本；解析失败回退文字并说明格式未完整保留 |
| 表格 | 明确的 HTML 表格，或具有稳定列数的制表符分隔文本 | 行列网格、超宽横向滚动、超长纵向滚动；只有明确的表头标记才用表头样式 | 查看原文；复制原始 TSV/文本；不能因像表格而丢弃正文 |
| 代码/结构化文本 | 明确的代码块标记，或完整 JSON 等可验证结构；普通源码猜测只提供建议 | 等宽字体、保留缩进、不自动换行；语言未知时仍可阅读 | 普通文本模式；不自动格式化、不执行代码；首版不要求语法高亮 |
| 单链接 | 去掉外围空白用于检测后，整段恰好为一个合法 HTTP(S) URL | 域名/地址正文和显式“打开链接”命令；长地址允许展开 | 原始 URL 及全部原文；不自动请求网页、标题、favicon 或预览图 |
| 路径文本 | 整段符合绝对 Windows 路径/UNC 路径语法 | 路径文字与“复制路径”；存在性检查后再启用相关打开命令 | 仍是文档；不因为像路径就改成文件引用，不递归扫描目录 |

补充规则：

- 多行普通文本中的 URL 只成为可操作片段，不把整段降成一个链接卡片。
- 数字、日期、邮箱、电话号码、颜色值等首版按文本展示，不为未经需求验证的识别增加新类型。
- CSV 不凭逗号自动识别成表格；普通句子也含逗号。后续若增加 CSV，需明确解析和用户切换入口。
- TSV 自动识别至少需要两行、两列且行列结构一致；不删除空单元格。缩进代码等歧义场景保持文本，提供“按表格查看”。
- 一段富文档中同时有文字、表格和图片时，保留为富文档；不能只取其中表格、第一张图片或链接。
- 只有空格、Tab、换行的非空文本可创建普通文本贴图，默认显示“空白文本”和字符统计，并提供显示空白符；完全没有字符才是空内容。

### 3.3 文件条目的展示种类

一级始终是 `Files`。后缀用于展示图标与说明，不等同于已验证的文件内容格式。

| 条目种类 | 默认 UI | 可选预览与命令 |
| --- | --- | --- |
| 普通文件、文档、压缩包、未知后缀 | 文件图标、完整文件名、类型和可得的体积；路径按需查看 | 双击 / Enter 打开文件…、Ctrl+C 复制文件引用；菜单提供所在位置和复制路径 |
| 图片文件 | 文件名、类型/体积和后台加载的有界缩略图，默认保持文件身份 | 显式“作为图片贴图”后才准备全分辨率预览；“恢复文件卡片”回到默认呈现。缩略图准备本身允许有界解码；切换预览不把文件引用悄悄改成像素对象 |
| 视频、音频 | 类型图标、文件名和可得的体积，路径按需查看；不绘制伪造波形 | 首版不嵌入播放器、不自动探测时长；显式打开使用系统关联程序 |
| 文件夹 | 文件夹图标、目录名、路径 | 打开文件夹…、复制目录引用/路径；不递归统计体积或展开整棵目录 |
| 多文件、多个文件夹、混合集合 | 一个只读可滚动列表；摘要只显示项目数和公共父路径，不重复工具条标题 | 行悬停 / 聚焦显示复制路径与打开位置；行右键菜单针对该行；工具条复制全部。不使用复选框或批量选择面板 |
| 已移动、已删除、无权限、离线项目 | 保留条目及原始路径，显示对应不可用状态 | 复制路径仍可用；打开类操作给出具体失败原因 |
| 虚拟文件，例如只提供 FileDescriptor/FileContents 的附件 | 识别为需要虚拟文件支持的读取结果 | 首版明确提示暂不支持；不能假装得到一个有效本地路径 |

`CF_HDROP` 与虚拟文件的传输协议不同。虚拟文件未来需要 OLE `IDataObject`、按索引读取内容及受控落盘，不复用普通路径列表的读取方式。[W2]

## 4. 同一次复制包含多种格式时怎么选

### 4.1 原则

保留同一快照内可用的表示，并形成一份“主内容 + 可切换表示”的结果。**优先级属于本产品的选择规则**，不是 Windows 保证能推断用户意图。

不能使用当前读取顺序，也不能简单规定“只要有图片，就显示图片”。Office 和网页选区可能同时提供正文、富文本和图片表示。

### 4.2 默认决策顺序

1. 有有效文件引用 → `Files`。文件名文本、HTML 或缩略图作为补充，不覆盖文件对象。
2. 没有文件引用，有可解析的富文档正文/结构 → `Document`。单一表格可以默认表格模式，混合结构保留富文档。
3. 没有完整文档，存在可解码图片 → `Image`。纯文本备选保留在“更多”中。
4. 没有上述对象，有非空文本或可从富格式提取的文字 → `Document`，再按保守规则选择模式。
5. 所有候选无效 → 返回空、格式不支持、内容损坏或超限等具体状态。

HTML 仅含一张图片及外围包装、且有可用图片表示时按图片处理；图片的 `alt`、来源 URL 不被当作富正文。没有本地图片字节时不能自动下载 `<img src>`，回退文字说明或报不支持。

HTML 与 RTF 都可解析时，默认先使用 HTML 的受支持结构；HTML 失败再试 RTF，随后回退纯文本。备选格式仍保留。这个顺序是可测试的产品规则，不按来源应用名称写特殊分支。

若两种表示包含无法证明等价的内容，不擅自合并为一篇新文档。默认按上述规则展示，并允许用户选择“查看文字/查看图片/查看原文”。正文切换应保留各自滚动与选择状态。

### 4.3 必须覆盖的例子

| 实际复制动作 | 可能提供的数据 | F3 默认结果 |
| --- | --- | --- |
| 复制一句话 | Unicode 文本 | 普通文本卡片 |
| 复制整个网址 | 文本、可选 HTML | 单链接模式；只有链接包装不应压过单链接识别 |
| 从网页复制一段带链接的文字 | HTML + 文本 | 富文本正文，保留上下文 |
| 复制浏览器图片 | PNG/DIB + URL 文本，或图片 HTML | 有图片字节时为图片；只有 URL 时为链接，不下载 |
| 从 Excel 复制单元格区域 | HTML 表格 + TSV + 可能的图片表示 | 表格模式，原文可切换 |
| 从 Word 复制段落 | RTF/HTML + 文本 + 可能的图像表示 | 富文本模式，不能只显示截图表示 |
| 从编辑器复制源码 | 文本、可选代码 HTML | 有明确代码结构则代码模式，否则文本并可手动切换 |
| 在资源管理器复制 `photo.png` | 文件引用 + 可能的文本 | 图片文件卡片；显式选择后可作为图片贴出 |
| 在编辑器复制 `D:\work\photo.png` 这串字 | 只有文本 | 路径文本；不伪装成复制了文件 |
| 复制多个文件和文件夹 | 一个文件引用列表 | 一个文件集合窗口 |
| SnapClip 复制截图后按 F3 | 图片 + 排除监控标记 | 图片贴图；不因监控过滤而失败，不重新写入历史 |

## 5. 展示和交互

### 5.1 三类窗口的共同约定

- 每次成功创建固定一份内容，不跟随剪贴板更新。
- 全部可以置顶、拖动、关闭；窗口初次出现不抢走原应用焦点。
- F3 在当前指针所在显示器附近放置，初始位置留出指针空间；边缘不足时翻向并限制在工作区，支持负屏幕坐标。
- 默认大小从内容需求计算，并设最小、舒适、最大尺寸。正文超出最大尺寸后滚动，不让长文或几百个文件撑满桌面。
- 工具条嵌在窗口内部顶部，覆盖在当前窗口范围内，不依赖在窗口外绘制。创建后先显示约 1.5 秒，再在悬停、键盘聚焦、菜单打开或拖动时显示；收起成标题条时始终可见。不会因淡入淡出改变正文布局。
- 工具条提供“复制”“始终置顶”“更多”“关闭”。复制后按钮原位变成对勾约 1 秒，短反馈位于当前贴图内部，不依赖主页面底部提示条。重要命令同时有键盘与菜单入口，不能只有 hover 一条路径。
- 8px 窗口内边缘作为拖动入口；Alt+拖动正文也可移动。普通正文拖动仍用于选择文字。原型在演示桌面内钳位位置，真实实现按显示器工作区钳位。
- 辅助信息在 100% 界面比例下不低于 12px；普通正文行高约 1.7，使用约 16px 内容边距。标题与正文保持同一套对齐线。
- “更多”使用现有 Yue Dropdown；按钮与提示复用 Yue 的状态、尺寸、主题和动效。首版不因贴图再制造 Button/Popup 分支。
- 使用标题、正文、辅助信息三个主要层级。图标沿用 Tabler；普通分类保持中性色，不把每类内容都做成彩色标签。
- 动画读取现有语义 token 并响应减少动画设置，不为 F3 写死 300ms；拖动、滚动、文字选择立即跟随输入。

### 5.2 图片贴图

F6原位截图沿用现有原生图片宿主，保留无激活、拖动、**普通滚轮缩放**、圆角、倍数徽标和双击关闭；`host.rs`范围为 **0.1×–10×，每档0.1×**。2026-11-03接入现有组件后，F3图片使用YueImagePreview：普通滚轮缩放、拖动平移、物理像素100%、背景和网格，双击适应窗口，Escape或关闭按钮关闭。原HTML的原生图片倍率约定不再代表F3的完整组件交互，实际接入见§11.6。

HTML 原型只模拟倍率与视觉反馈：以演示视口为 1× 基准，超出可见范围时在视口内查看；它不验证真实窗口随原始像素改变尺寸、鼠标锚点或 Windows 高精度滚轮路由。

图片解码后保留原始分辨率；初始适屏通过显示变换完成。原图尺寸超过资源准入限制时明确拒绝，不偷偷缩成 OCR 图片后声称是原图。透明图片保留 alpha，显示背景策略与既有图片贴图一致。

### 5.3 文档贴图

文档窗口由 GPUI + Yue 呈现，可以点击激活，以支持文字选择、复制、键盘和读屏。`focus: false` 只作为初次显示不抢焦点的配置，不能等同于永久 `WS_EX_NOACTIVATE`。

- 正文默认 readonly，可选择而不可意外修改；不是把整段文字画成一张图片。
- 普通正文采用 UI 字体，代码采用已有等宽字体方案。
- 标题与 8px 内边缘用于移动，Alt+拖动为额外入口；无修饰键拖动正文用于选择文字。正文双击选择词，不能继承图片的双击关闭。
- 一个正文滚动所有者。普通文本换行后只纵向滚动；代码、表格允许横向滚动，不把横向滚动强制转成纵向。
- 标题显示“文本”“代码”“表格”“链接”等简短类型，辅助行按需显示字符数、行数或行列数。UTF-8 字节数不能冒充字符数。
- 表格可明确识别的数字列右对齐，纵向滚动时表头吸顶，横向滚动时首列固定。只有确有表头语义才绘制吸顶表头；TSV 不凭第一行位置伪造表头。
- 链接正文使用可点击的链接语义，点击为显式打开；长地址可折叠查询参数，复制保留完整原始地址。原型中点击仅展示打开反馈。
- 存在备选表示时，在正文顶部提供“查看排版/表格、文字、图片、原文”切换，各视图分别保留滚动位置。只为实际持有的表示提供入口；原型的文档图片明确标为示意。
- 文本显示不得静默裁断。大内容需要惰性布局或分块；尚不具备能力时明确超限，不以三行历史预览代替全部内容。
- 原始文本单独保留。软换行、展示空白符和模式切换不改写复制结果。

选择与键盘约定：`Ctrl+C` 优先复制选区，无选区时复制当前正文；`Ctrl+A` 选择正文全部；Tab 在标题命令间移动，正文使用文档选择与导航语义，不能假定 Base Input 的 Tab 会自动遍历控件。

富文本只支持实现并测试过的原生结构。首版格式承诺为基础段落、强调、列表、链接和表格；原网页字体、绝对定位、脚本、表单、任意 CSS、外部字体/图片不属于承诺。HTML 清理后才能转换成原生文档节点，不直接给未经限制的通用 HTML 渲染器加载外部资源。[W3][W4]

### 5.4 文件集合贴图

单文件采用紧凑卡片；多项目采用项目数、公共父路径与只读列表，不重复工具条中的名称。文件名、路径都左对齐，元数据和行快捷操作使用稳定尾部槽位；长文件名不能把按钮挤出窗口。

- 打开文件/文件夹必须来自用户明确操作，不在 F3 读取时打开。单文件或聚焦行支持双击 / Enter 打开、Ctrl+C 复制文件引用；复制路径与复制文件引用使用不同命令。
- 文件拖出到资源管理器/其他应用属于传递交互。原型只提供网页内接收区演示拖动与反馈，不会生成真实的 Windows 文件拖放数据对象；生产实现必须单独评估 OLE 数据对象和生命周期。
- 行悬停或聚焦显示“复制路径 / 打开所在位置”，行右键菜单必须锚定该行；顶部复制按钮针对整个集合。正文保持只读，不增加复选框、选择模式或常驻批处理面板。
- 多项列表保留复制顺序和完整计数，不进行递归扫描。条目 ID 由快照和条目身份派生，不使用会随排序改变的行号。
- 拷贝到剪贴板的是路径引用，不自动备份全部文件内容。文件删除或改名后，卡片仍保留原路径与失效状态。
- 缩略图和元数据后台加载，失败保留基础条目；网络路径不在首次展示时同步探测或触发下载。
- 首版不批量打开所有文件，不自动执行程序，不嵌入 PDF/Office/音视频查看器。
- “复制文件”写文件引用；“复制路径”写文本。若原始操作是剪切，贴图自身不会执行移动，也不发出“已粘贴/已移动”通知；主动再次复制按复制语义写入。
- 大集合采用虚拟列表；若读取设数量上限，必须显示实际总数与未载入数量，不能沿用现有 `min(1024)` 后不告知截断的行为。

### 5.5 焦点、关闭与无障碍

- 文档/文件窗口点击激活后支持 Tab、Shift+Tab、上下键及可见焦点。Escape 先关闭菜单等顶层浮层，无浮层时关闭当前贴图。
- 顶层关闭不强行激活早已失效的源窗口；由 Windows 正常处理焦点回退。关闭内部菜单才恢复到该窗口中的触发按钮。
- 所有图标命令有可访问名称；正文、文件列表、当前聚焦项提供正确语义。状态不能只靠红色或透明度表达。
- 只有键盘/读屏真实可用时才能宣称可访问。无头树节点断言不能替代 Narrator 验收。
- 图片现有非激活交互与新文档可激活交互分别测试，不把一套焦点规则强套给两者。

### 5.6 恢复、辅助能力与原型覆盖

- “置顶”统一称为“始终置顶”，表示保持在其他窗口上方；取消后变成可被遮挡的普通窗口，不等于关闭或取消贴图。原型用一个模拟普通窗口展示遮挡关系。
- 关闭后提供约 5 秒的“撤销关闭”入口；`Ctrl+Shift+T` 可恢复本次会话内最近关闭的贴图，原型最多保留 20 批关闭记录，不跨刷新。托盘设计包含显示全部、隐藏全部、关闭全部、撤销关闭及恢复鼠标操作。原型顶部“贴图管理”模拟这些入口。
- Alt+滚轮调透明度、鼠标穿透、收起成标题条为辅助交互探索，**原型可演示，尚不代表原生实现已交付**。穿透必须先有卡片外的恢复入口与 `Ctrl+Alt+P` 恢复方式；透明度原型下限 30%。这些是原型参数，生产参数待真实桌面确认。
- 贴图内部反馈用于已有窗口。空剪贴板、占用、变化、未知格式、虚拟文件、超限/损坏图片没有窗口可挂，采用触发位置附近的独立轻量气泡；不创建空卡片。
- 原型覆盖六种文档模式、空白文本、长文、长文件名、显示部分的大集合、损坏富格式回退与备选表示。富格式转换、窗口创建、剪贴板竞争及资源预算仍需生产测试，不能把演示状态当作实现结果。
- 粘贴试验区仅接收主动粘贴提供的格式，轻量预览 URL、绝对路径、明确代码、TSV、基础 HTML 与文件/图片。浏览器不提供本地文件完整路径，也不验证 Windows RTF/CF_HTML 封套或多格式优先级；不能以此替代原生分类测试。所有输入只保留在当前页面。
- “浅色网页 / 深色编辑器 / 照片背景”用于观察对比与阴影；照片使用内嵌插画模拟。100 / 125 / 150 / 200% 只缩放演示贴图的排版，不宣称真实 DPI 或字体渲染验收通过。

## 6. F3 的快照与请求流程

```text
F3 / 托盘“贴出剪贴板” / 应用 Action
  → 同一应用命令 PinClipboard
  → 记录 request_id、剪贴板序号、指针位置、源窗口和显示器
  → 在工作线程打开并复制当前剪贴板数据
  → 尽快关闭剪贴板
  → 后台解析、校验、分类、准备内容
  → 回到 GPUI 应用线程交给 PinManager
       ├── Image → GPUI + YueImagePreview（F3）
       └── Document / Files → GPUI 贴图窗口
  F6 原位截图 → 现有原生图片宿主线程
  → 实际创建成功才进入已打开注册表
```

### 6.1 当前剪贴板，而不是最近历史

F3 不依赖历史监听已完成、不强制写入数据库、不要求 OCR 成功。读取入口显式区分 `Monitor` 与 `ExplicitPin`：

| 策略 | 后台监控 | 显式 F3 |
| --- | --- | --- |
| 排除监控标记 | 保持跳过 | 不将监控标记误当作内容禁止读取；仅在内存中显式展示，不重新入历史 |
| SnapClip 自己写入的内容 | 防止回环采集 | 允许贴出 |
| 图像缩小策略 | 保留独立历史/OCR 策略 | 保留原像素，显示缩放与数据缩放分离 |
| 数据库不可用、历史监听关闭 | 按既有能力降级 | 仍可读取与贴出 |
| 原始字符、全空白文本 | 不擅自改变既有历史策略 | 保留，允许识别成空白文本 |

排除监控标记表达“不应被后台记录”，不等同于密码识别或访问授权。本方案不设计内容扫描、密码猜测或绕过 Windows 权限。

### 6.2 一致性与延迟提供格式

`OpenClipboard` 成功期间会阻止其他应用修改剪贴板；返回的系统句柄必须在关闭前复制成自己的数据，不能保存为窗口的数据来源。[W4][W5]

- 在 F3 消息进入时记录目标序号；真正取得剪贴板锁时若内容已被后续复制替换，取消该请求并提示“剪贴板已变化，请重新按 F3”。不把另一次复制悄悄当作原请求内容。
- 同一锁内获得可用表示，复制原始字节/路径；Bitmap 必需的像素复制在锁内完成，普通图片解码、RTF/HTML 解析、文件元数据查询都移到锁外。
- 延迟渲染可能影响序号，不能把“调用前后序号不同”一概判成其他应用的新复制。允许同一锁内提供方的延迟物化，记录完成后的序号与快照身份。[W6]
- 剪贴板忙时采用有界重试。迟迟不响应的延迟提供方可能阻塞 Win32 调用：工作线程保证不阻塞 GPUI，超时后丢弃迟到结果；不承诺线程能被安全强制终止，也不无限增开线程。
- 解码期间系统剪贴板又变化，不替换已经完成读取的快照；只有更新的 F3 请求或用户取消，才让该请求结果失效。

### 6.3 连续按键与重复内容

- F3 注册使用 `MOD_NOREPEAT`，按住不连续创建窗口。[W7]
- 同一读取请求期间再次按 F3，若仍针对同一快照则合并；新快照请求使旧请求过期。迟到完成不得打开旧窗口。
- 同一运行期快照已经有贴图时，再按 F3 只将其上移显示，不抢焦点、不重复开窗；关闭后可再次创建。
- 快照身份使用进程内生成的 snapshot ID，并关联序号/内容标识；单独的 Win32 序号不是永久唯一 ID。
- 两次不同的复制即使内容相同，也允许形成不同快照；不为了去重提前增加持久缓存。

### 6.4 错误状态

| 结果 | 用户反馈 | 保留什么 |
| --- | --- | --- |
| 空剪贴板 | 指针附近气泡：剪贴板中没有可贴出的内容 | 不创建窗口 |
| 暂时占用 | 指针附近气泡：无法读取剪贴板，请稍后重试 | 不回退旧历史 |
| 内容已变化 | 指针附近气泡：剪贴板已变化，请重新按 F3 | 不混合两次复制 |
| 不支持的格式/虚拟文件 | 当前剪贴板格式暂不支持 | 日志记录格式名，不记录正文或文件内容 |
| 富格式损坏但有文本 | 显示文本，辅助提示格式未完整保留 | 原文及可用备选 |
| 图片损坏/超限 | 无法读取图片 / 图片超过当前贴图上限 | 不用 URL 代替图片悄悄打开网页 |
| 文件失效 | 卡片显示文件不可用及路径 | 卡片、文件名、复制路径能力 |
| F3 被占用 | 设置/托盘明确提示快捷键不可用 | 托盘与应用命令仍可用 |

## 7. 模块与依赖设计

### 7.1 提取 snapclip-clipboard

现在系统剪贴板由历史入库和显式贴图两个真实使用方共同消费，具备独立能力边界。新增 `snapclip-clipboard`，迁出 history 中的 Windows listener、格式读取和无 UI 的内容解析；将应用自己的系统写入适配也归到该能力。

```text
snapclip-app
  ├── snapclip-clipboard ──→ snapclip-model
  ├── snapclip-history ────→ snapclip-clipboard / snapclip-model
  ├── snapclip-capture ────→ snapclip-model / snapclip-ui
  └── snapclip-pin ────────→ snapclip-model / snapclip-ui
                       └─→ gpui-kit / yue-component（新增文档与文件界面）
```

应用把剪贴板能力接入 history 的既有来源端口与 F3 命令；history 使用共享 clipboard 读取/监听，history、capture、pin 不互相调用。`snapclip-clipboard` 不依赖 GPUI/Yue，不负责窗口、OCR 或数据库。历史使用的纯图像/存储处理仍由实际所有者持有，不因提取而让 clipboard 反向依赖 history。

分类、UTF 解码、CF_HTML 封套解析、RTF 文本/span 转换属于无 UI 的内容准备；历史卡片只把通用 span 映射成 GPUI 样式。不要继续让贴图去调用 `apps::history::rich`。确实被两个能力共享的纯内容记录可放进已有 `snapclip-model`，无需再加第三个 content crate。

建议的最小文件组织：

```text
crates/snapclip-clipboard/src/
  lib.rs                 能力边界、读取用途、快照、类型重导出
  classify.rs            内容对象与默认模式的纯规则
  document.rs            文本/HTML/RTF 的解析和受支持结构
  windows/               监听、读取、写入、格式标识及系统适配
  tests/                 随实际代码规模按分类/快照/文档拆分

apps/snapclip/src/clipboard_pin/
  mod.rs                 F3 工作流、取消/过期、错误反馈
  tests.rs               应用协调的测试
```

这是职责图，不要求每个概念立刻拆文件。也不增加 ClipboardService → ClipboardManager 等同义包装。

### 7.2 snapclip-pin 的必要演进

单一图片宿主不适合通过增加 GDI 命中区，逐步手写出文本选择、表格、焦点、菜单和无障碍系统。本方案明确允许能力 crate 新增 GPUI/Yue 依赖，并把 docs/51 的“完全不依赖 GPUI”从当前事实调整为新的边界。

- 公共 `PinManager` 在 GPUI 应用线程协调全部贴图，拥有统一编号与打开窗口注册表。
- 原图片线程成为私有 `native_image` 宿主，继续只拥有自己的 HWND/DIB/Win32 消息；不能跨线程操作 GPUI entity。
- 文档/文件窗口的 view、菜单、选择、滚动及窗口状态留在 `snapclip-pin` 内，不搬回应用壳。
- 应用只准备来源并提交类型明确的内容。pin 不读取剪贴板、不打开历史数据库、不向 capture 取屏幕像素。
- 复制图片、正文、文件引用等命令由 pin 报告用户意图，应用调用 `snapclip-clipboard` 完成系统写入，再向对应窗口报告结果。命令带 pin ID 和共享内容引用，不把大量字节塞进通用 `AppEvent`，也不能使用会静默丢消息的通知通道。
- `PinContent` 在语义上只有 Image、Document、Files；文档模式是展示选择，文件种类是条目属性。内部字段私有，构造和读取方法沿用项目命名约定。
- 已打开注册表才是生命周期权威。当前有界事件队列允许丢事件，不能将它直接作为 GPUI 窗口注册/清理的唯一依据；创建/关闭完成必须在管理器中可靠协调，外部事件仅作通知。
- 创建失败与创建后关闭继续区分；提交成功不等于已上屏。准备阶段的请求 ID 与成功进入贴图生命周期的 pin ID 分开。

### 7.3 热键归属

F3/F6 都属于应用命令，统一放在已有托盘消息线程注册/释放，避免 pin 需要知道系统剪贴板或截图来源：

- F3 → `PinClipboard`，F6 → `PinLastSelection`。
- F6 的截图来源由应用读取并准备，再调用相同贴图创建入口；保留一次性消费和原屏幕坐标语义。
- 延时截图自动贴图仍走同一个应用级“贴最近选区”命令，不另造图片来源。
- `PinHome` 与仅表达 F6 的 `PinPoster` 若不再承担真实职责，直接移除并更新调用方，不保留兼容空壳。
- F5 等捕获会话相关热键不在本轮顺手重构。
- `RegisterHotKey(NULL, ...)` 得到线程消息，消息循环必须显式处理，不能交给 `DispatchMessage` 后期待窗口过程收到。[W7]
- 快捷键失败独立降级；F6 冲突不能影响 F3，截图模块不可用不能阻止剪贴板贴图。

### 7.4 GPUI 与平台能力边界

已核对本地 `gpui-pre/src/platform.rs` 的 `WindowOptions.focus`、`show` 和保存面板的开窗路径。初次不激活可通过现有配置表达；置顶、工具窗口样式和多显示器定位仍需在 Windows 窗口适配层落实和实测。

不杜撰 `.always_on_top()` 等 builder；实施时以当前源码为准。GPUI 原语缺少必要能力时优先补窄平台适配，并单独回归窗口生命周期，不把 Win32 裸句柄散落到正文 view。

## 8. 文档、图片和文件的资源约束

- 原始表示总字节数有上限，图片尺寸乘法/stride/缓冲区大小使用 checked arithmetic；不能只限制 PNG 压缩字节而不限制解码像素。
- HTML 的 `StartFragment/EndFragment` 是整个封套的 UTF-8 **字节偏移**，不是字符位置；处理负值、越界、缺失字段、非字符边界和畸形输入。[W3]
- 对文档解析深度、节点数、表格单元格数和展示规模设有界预算。新阈值需要带上测试样本和实测记录，不在本设计中假装已有性能结论。
- 文件引用只拥有路径列表及显示元数据；文件本体生命周期仍归文件系统。缩略图是可丢弃派生物，不是文件备份。
- 首版不后台下载 URL/图片、不预读 UNC 文件、不递归目录、不释放或延用系统拥有的剪贴板句柄。[W4]
- 内容准备在后台完成，UI 只更新当前请求。关闭窗口后释放像素、文档、缩略图和任务；迟到任务不得重建窗口。
- 初始窗口尺寸建议以 token/rem 定义：文档舒适宽度约 28rem、文件约 24rem，正文从内容测量；最大宽高限制在当前显示器工作区。数值是设计起点，必须由真实文字、列表和 DPI 测试校准。
- 仅用于捕获/定位的坐标使用物理像素，GPUI 界面布局使用逻辑单位；只在平台边界按目标显示器 DPI 转换一次。

## 9. 分步实现与回归验收

各步都建立升级前基线，再加入会失败的新用例，完成实现后对比原行为。以下是计划，不是已通过的测试报告。

| 步骤 | 交付物 | 必须先补的测试 |
| --- | --- | --- |
| 1. 来源与分类 | 提取 clipboard 能力、显式读取用途、三类对象及备选表示 | 多 payload 顺序无关；文件优先；Word/Excel 不被图片覆盖；路径文本仍为文档；SnapClip 自写可显式读；原像素不被 OCR 缩小 |
| 2. F3 图片闭环 | 热键命令、请求工作流、统一编号、保留图片宿主 | 真实 F3；无 capture/history 时可用；按住不重复；空剪贴板；忙重试；过期请求；图片 F6 既有行为全回归 |
| 3. 文档窗口 | 纯文本与原文、基本富文档、表格、明确代码、单链接、路径展示 | 中英混排/emoji/组合字符；换行缩进；选择复制；损坏 HTML/RTF 回退；UTF-8 偏移；表格空格/空单元格；菜单和焦点 |

## 10. 首版范围与明确不做

## 11. 实现与验证记录（2026-11-03）

### 11.1 已实现的生产路径

| 层 | 当前实现 |
| --- | --- |
| 共享剪贴板 | 新 `snapclip-clipboard`，从 history/app 抽取系统读写及纯内容准备；history 保留入库、OCR 缩图和显示映射 |
| F3 | 托盘线程注册 `MOD_NOREPEAT` F3，主窗口/托盘有同一命令入口；单 bounded worker 同锁读取，锁外解析；5 次锁尝试、间隔 20ms，3 秒应用期限包含排队时间 |
| 请求身份 | 快速操作只保留最新请求；timeout/close-all 使旧结果失效；不为被占用的 provider 不断另起线程；相同 sequence + fingerprint 的已打开内容 raise 原窗口 |
| 图片 | 保留 PNG/DIBV5/DIB/CF_BITMAP 原尺寸与透明度；F3 窗口按目标工作区及 DPI 估算尺寸，组件 FitAll 适配实际视口；F6 仍一次性取截图，1× 放回原屏位置并保留圆角 |
| 文档 | 六种模式共用生产 `PinView`；Kit TextView 提供真实选字、滚动、复制；HTML 白名单/RTF 基础强调；真实表格由 Kit DataTable 提供虚拟化、表头和固定首列 |
| 文件 | `CF_HDROP` 文件引用优先；单文件/文件夹/集合，元数据或不可用原因、公共父路径、虚拟列表；行选择、上下键、Enter/双击打开、复制引用/路径、打开所在位置、右键/更多菜单 |
| 本地图片文件 | 文件身份不变；后台准备缩略图，显式“作为图片贴图”才准备全图；可恢复卡片和复制图片。当前解码支持 PNG/JPEG/WebP/BMP，其他格式仍可保留文件卡片 |
| 窗口管理 | 应用线程 entity 管理 pending/open；F6 原位截图使用私有 Win32 线程，F3 图片/文档/文件使用 GPUI；置顶、隐藏/恢复、全部关闭、最近 8 张撤销、5 秒撤销入口 |
| 复制与反馈 | pin 发送带 ID 的复制意图；应用后台调用共享 writer，同锁发布格式及自写 marker，再反馈原窗口；预览 example 才模拟复制结果 |
| 错误 | 空/忙/变化/超限/损坏/虚拟文件等不创建伪内容窗口，反馈出现在指针附近；文件不可用在卡片保留路径 |

真实 `CF_HDROP` 存在时不再为它读取附带 HTML、文本或位图，避免附件表示消耗预算或触发延迟提供。Monitor 仍跳过自写 marker 和全空白；ExplicitPin 可读取两者。文件元数据和图像解码不在剪贴板锁内运行。

### 11.2 交互细节与实现调整

- 文档工具条嵌在窗口内部；初显 1.5 秒，之后由 hover/焦点/菜单状态保持，透明度通过 Yue motion token 驱动，响应减少动画。复制完成后原位显示 Check 约 1 秒；错误有正文之外的状态反馈。
- 正文拖动用于选字；标题、默认 8px 内边缘或 Alt+拖动用于移动。移动判断在 capture 阶段优先于正文/按钮，Alt 操作不会误激活复制。无原生句柄的无头窗口不调用系统移动。文件行保留稳定操作槽位，数字表格列右对齐，空值不误判成数字。
- 普通文本保留真实 Tab、连续空格、空行；全选复制取原始文本，包括 CRLF 和末尾换行。全空白提示放在正文外，不污染复制。
- 表格 `Some("")` 是选中的空单元格，不等于没有选区。Ctrl+C 复制选中 cell/row，无选区复制原始文本；工具条复制/`Ctrl+Shift+C` 始终复制完整对象。
- Kit 0.8 的 DataTable 没有整表多选范围。因此表格里的 Ctrl+A 切到“文字”表示并显示真实全选，Ctrl+C 保留原 TSV；返回表格仍保留原 cell 选择。不会只设置一个不可见的“全部选中”标记。
- Escape 先关闭最上层菜单，再关闭贴图。发现并修复了 Yue Dropdown 的两个基础问题：小窗口的行高度预算未扣完 chrome/shadow 导致 Popup NoSpace；父级 action 先于菜单 raw keydown 消费 Escape/Enter/箭头。修复在组件库，未在贴图里绕过。
- 原 HTML/RTF 原始 bytes 保存在快照中，整体复制可按原格式写回；“原文”视图是可读文本投影，不承诺 ANSI RTF 源的 UTF-8 文本复制等同于原始 bytes。
- 图像备选必须实际存在才显示切换入口。文件转换成图片视图后仍可复制完整文件对象和恢复文件卡片。

### 11.3 资源策略与依赖接入

| 边界 | 当前值/行为 |
| --- | --- |
| 原始剪贴板表示总量 | 64 MiB；一次读取和各候选分配前检查 |
| 图片解码 | 24,000,000 像素，checked 尺寸/缓冲区计算，保留原像素；不拿 OCR 缩图贴出 |
| 文档 | 最多 200,000 字符；HTML 源 2 MiB、30,000 节点、128 层；超预算拒绝或保留原文回退，不悄悄截断 |
| 表格 | 最多 16,384 cells、256 columns；超限保留文字，不能静默丢行/列 |
| 文件 | 最多 1,024 引用；支持不超过 32,767 UTF-16 单位的路径，空/损坏路径明确报错；不后台访问 UNC，不递归目录 |
| 管理器 | 最多 32 张（含 pending）、256 MiB 保留内容，源/像素/派生预览/撤销一起记账 |
| 撤销 | 最近 8 张，仍受字节预算；5 秒反馈是入口显示时间，不是记录的保存期限 |

以上是首版有界保护策略，不是性能 SLA；窗口、GPU、字体及解析的暂态分配还有额外内存，不声称进程占用严格等于 256 MiB。长路径单测证明编码/保留不被 8192 截断，不等于所有文件系统允许创建同样长的实体文件。

消费根 `Cargo.toml` 保留 `gpui-base / gpui-pre / gpui-pre-windows` 的本地 `[patch.crates-io]`，Yue 通过相邻工作区 path 依赖；不能只复制 `snapclip-pin` 目录便假设依赖齐备。Base 新增只读 `TextViewState::is_all_selected()` 公开 getter，用于精确的原文复制，不修改文本选择行为。依赖门禁允许 pin 的 UI 依赖，但阻止它反向依赖 clipboard/history/capture。

### 11.6 接入现有图片预览组件（2026-11-03）

### 11.7 公共图片资源准备（2026-11-03）
