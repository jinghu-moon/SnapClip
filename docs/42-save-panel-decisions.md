## 2. 逐条决策

### D1 WebP 只做无损 `[已定]`

- **规格位置**：§6.2 高级项表"WebP · 无损压缩 · 关"（规格 262–265 行附近）、§5.5 质量档说明"WebP 无损模式不支持质量调整"（规格 231 行附近）。
- **冲突/待决点**：规格默认**有损** WebP（无损开关默认关，质量档 90/70/45）。本仓库后端只有无损 WebP（`crates/snapclip-capture/src/save_format.rs:142-149`），且 `docs/34 §9.1` 记录：有损 WebP 只支持 4:2:0，对 UI 文字不利。
- **决定**：**只做无损 WebP**。删除"无损压缩"开关与质量档 90/70/45；WebP 的质量行按"无损"说明文案呈现。
- **依据**：① 后端已实现且已实测（`docs/34` 的 WebP 无损路径）；② 有损 WebP 只有 4:2:0，与 D4 的文字锐度原则冲突；③ 引入有损 WebP 需要换/加编码器，收益未测量。
- **规格需改动**：§6.2 删除"WebP 无损压缩"行；§5.5 的质量档文案改为固定"WebP 无损模式不支持质量调整"。
- **影响任务段**：S6（高级项）、S2（编码服务只算无损体积）、S3（质量行显示规则）。

### D2 删除 JPG 渐进式 `[已定]`

- **规格位置**：§6.2 高级项表"JPG · 渐进式加载 · 关"（规格 262–265 行附近）。
- **冲突/待决点**：**结构性冲突**。行带 sink 只写 baseline，`apps/snapclip/src/capture/row_band_jpeg.rs` 的测试明确断言不得出现渐进式标记 `FF C2`（`row_band_jpeg.rs:282-288`）。渐进式需要对整幅图做多遍扫描，与"长图流式写出、不物化整图"（`docs/35`）根本对立。
- **决定**：**删除**该选项，规格与 UI 都不出现。
- **依据**：① 上面的断言与 sink 结构；② 渐进式对本地文件无收益（网络下载才需要）。
- **规格需改动**：§6.2 删除该行。
- **影响任务段**：S6。

### D3 删除"移除元数据" `[已定]`

- **规格位置**：§6.2 "全部 · 移除元数据 · 开"（规格 262–265 行附近）。
- **冲突/待决点**：三个 sink（PNG 行带 / JPG 行带 / WebP）**本来就不写** EXIF / ICC / XMP，没有元数据可移除。保留一个永远不起作用的开关是伪功能。
- **决定**：**删除**该选项。
- **依据**：读三个 sink 的写出路径，无元数据块；`convert()` 也不注入。
- **规格需改动**：§6.2 删除该行。
- **影响任务段**：S6。

### D4 JPG 默认 4:4:4 `[已定]`

- **规格位置**：§6.2 "JPG · 色度采样：4:4:4 / 4:2:0 · **默认 4:2:0** · 4:4:4 文字边缘更锐"（规格 262–265 行附近）。
- **冲突/待决点**：规格默认 4:2:0，但本项目实测（`docs/34 §11`）：同一张 UI 截图，4:2:0 让**文字** PSNR 从 **28.52 dB 掉到 26.27 dB**，而**整图 SSIM 只变化 −0.0003** —— 整图指标把这个损失完全掩盖了。SnapClip 截的正是文字密集的界面。
- **决定**：**默认 4:4:4**；4:2:0 保留为高级项，标签旁注明"文字更糊"。
- **依据**：`docs/34 §11` 的实测数据（文字与整图分开测）。这是"按内容选参数"而非"按体积选参数"。
- **规格需改动**：§6.2 的默认值改为 4:4:4；高级项文案保留"4:4:4 文字边缘更锐"。
- **影响任务段**：S6（默认值）、S2（体积预估按 4:4:4 计算）。

### D5 解码预览必须实现 `[已定]`

- **规格位置**：§3 "【建议】真实实现不要用模糊示意：右半必须显示'编码后再解码'的真实像素（JPEG 块效应、WebP 涂抹、PNG 量化色带），这才是对比滑块的价值"（规格 139 行附近）。
- **冲突/待决点**：`docs/41` 曾把解码画面放进"可选阶段 S4b" ✗，理由是"会引入解码依赖"。这等于把规格的核心原则降级为可选。
- **决定**：**解码预览是规格范围内、必须实现的功能**。`docs/41` 的 S4 必须同时包含"编码后字节数"与"解码画面"；对比滑块属于 S4 的后半，但**同属规格范围**。允许**实施顺序**上先做字节数再接解码画面，但**不得**把"只有字节数"标成完整里程碑。
- **依据**：规格的"所见即所存"原则；预览若显示的不是真实产物，用户看到的就是假象。
- **规格需改动**：无（规格本就是如此，是任务清单偏离了）。
- **影响任务段**：S4（合并原 S4b）、S2（编码服务要为预览产出可解码的字节）、M3 里程碑。

### D6 保存成功后面板保持打开 `[已定]`

- **规格位置**：§2.3 生命周期："保存成功后面板保持打开，用 Toast 反馈。【原型】是否保存后关闭面板【待决】"（规格 58 行）。
- **决定（已拍板）**：**保存成功后保持面板打开** ✓，用 **Toast** 反馈，并允许用户**继续调整后再次保存** ✓。
  - 依据：用户最常在"存完看一眼大小 / 换个格式再存"之间来回 ✓；预览已是**真实编码结果** ✓，因此"再存一次"成本很低 ✓；撤销依赖 Toast 的"撤销"动作 ✓，关窗会切断该入口 ✓。
- **备选（未采纳）**：关闭 + 屏幕右下角 Toast ✗ —— 更利落，但把"再存一次"变长了 ✓。
- **规格需改动**：删掉该 `【待决】` ✓（§2.3 生命周期）。
- **影响任务段**：S3（底栏区域与关闭策略）、S5（保存操作）、S8（Toast 与撤销）。

### D7 Toast 位置 `[已定]`

- **规格位置**：规格未写位置（§7.6 只定义 Toast 的四个动作）。
- **决定（已拍板）**：
  - **面板打开时**：面板内、**底栏上方** ✓（距底 16 dip、右对齐、宽 420 dip 内 ✓）；
  - **面板已关闭时**：屏幕**右下角** ✓，距工作区边 24 dip ✓；
  - 两种情况都**不得遮挡预览右下角的"尺寸标签"** ✗（规格 §4.5 ✓）—— 面板内的 Toast 出现在底栏之上、预览之下 ✓。
  - 依据：Toast 是"**就地反馈**"✓，应当跟随它的触发者 ✓；跨窗口浮层在 Win32 下还要额外处理 owner ✗，就近放置最省事且不丢上下文 ✓。
- **规格需改动**：§7.6 补一句位置规则。
- **影响任务段**：S8。

### D8 质量档位数值 `[待测]`

- **规格位置**：§12.3 质量档 90 / 70 / 45（原型占位）；`docs/40` 曾推荐 95 / 92 / 85；本项目 `SavePreferences` 默认 92（`save_format.rs:238-260`），且有 `docs/34 §11` 的 92 实测。
- **冲突/待决点**：三套数字互不相同，且**只有 92 有实测支撑**；75 与 50（或规格的 70/45）没有任何实测。
- **决定**：**先只承诺 92**。在 `codec-bench --quality` 补测"文字 / 渐变 / 照片"三类内容后，再定"中/低"两个档位的数值并列回本表。
- **依据**：`docs/34 §11` 的测量方法已存在；不对未测量的数字做承诺。
- **规格需改动**：待测后回填 §12.3。
- **影响任务段**：S2（只算实测档位的体积）、S6（限制体积的搜索区间与质量行）。

### D9 单一编码产物：`EncodedArtifact` + `PendingCapture` `[已定]`

- **规格位置**：§3（预览）、§4（拖出）、§7.6（复制）、§2.3（保存）都以"同一张图"为前提。
- **冲突/待决点**：如果"预览一次、复制一次、拖出一次、保存一次"各编码一次，则 ① 四次结果可能不同（参数被改过）；② 大图会慢得不可用；③ 滚动截图会被迫物化整图。
- **决定**：见 §3 的接口设计。每组输出参数只生成一份文件型 `EncodedArtifact`；预览从它解码，拖出使用它，保存把它复制到目标目录的 `.partial` 后原子提交。复制图片也必须表示这份 artifact 解码后的结果，不得另行从源图编码。
- **规格需改动**：§12.5 删除“复制使用缩放后的位图、不经过有损编码”的建议；复制与预览、拖出、保存显示相同的最终图像。剪贴板在解码像素预算内提供 `CF_DIBV5`；PNG artifact 可直接作为注册 PNG 格式提供，超出 DIB 预算时仍可发布 PNG。JPEG/WebP 字节不得标成 PNG，也不为剪贴板另行编码。
- **资源约束**：artifact 落临时文件，不把长图编码结果强制放进 `Vec<u8>`；临时文件由唯一 owner 管理。参数变更时旧预览保留到新结果就绪，再释放旧 artifact。编码缓存和解码预览必须有按字节计量的上限，具体值由 S2/S4 基准确定并写入验收。

### D11 文本输入：原生 `EDIT` 子控件 `[已定]`（原“自绘 DirectWrite”作废 ✗）

- **决定**：保存面板是**独立普通（非分层）窗口** ✓，输入字段用**原生 `EDIT`** ✓。自绘只限**外壳**：窗口背景用 **DWM backdrop（毛玻璃）** ✓；输入框**外框**（圆角 6 dip、悬停/聚焦描边 ✓）由 D2D 画 ✓，`EDIT` **内缩 1–2 dip** 嵌在框内 ✓；按钮/分段器/标签仍用 `snapclip-ui` ✓。
- **明确不做** ✗：自绘 TextField ✗、IMM32 ✗、TSF（`ITextStoreACP`）✗、组合态渲染 ✗、候选窗定位 ✗。
- **理由（四条）**：
  1. **保存面板与截图框互斥** ✓ —— 面板出现时截图框消失 ✓ ⇒ 面板**不需要**叠在选区之上 ✓ ⇒ **不需要**分层窗口 ✓；
  2. 普通窗口**没有** `WS_EX_NOREDIRECTIONBITMAP` 的限制 ✓ —— 那是截图浮层的样式 ✓，会让子控件画不出来 ✗；
  3. **毛玻璃只有普通窗口能做** ✓✓（DWM backdrop 不支持分层窗口 ✗）⇒ 普通窗口不是妥协 ✓，而是**规格视觉的唯一实现路径** ✓；
  4. IME 组合 ✓、候选窗 ✓、撤销 ✓、剪贴板 ✓、拖选 ✓、**UIA** ✓ 全部由系统承担 ✓。
- **视觉验收**：输入框外框六态（默认/悬停/聚焦/错误/警告/禁用 ✓）用**位图断言** ✓；`EDIT` 内的文字/光标/选区由系统绘制 ✓，只核对字体、字号、内边距与外框一致 ✓。
- **规格需改动**：§13.2、§15.17 的“自绘 TextField / IMM32 / 自实现 UIA”**作废** ✗，改为“独立普通窗口 + 原生 `EDIT` + DWM backdrop” ✓。
- **影响任务段**：S5（**大幅缩小** ✓：窗口 + 外壳 + 原生字段 + 校验 ✓）；S9（UIA 由系统提供 ✓，只需验证 ✓）。

### D10 PDF 页尺寸与 WebP 回退 `[已定]`

- **规格位置**：§9："【待决】PDF 页面尺寸（1 px = 1 pt，还是按 96 dpi 换算）；页内图像格式——WebP 不能直接放进 PDF，需回退为 JPEG（有损）或 PNG / Flate（无损）"（规格 390 行附近）。
- **决定（已拍板）**：
  1. **页尺寸**：**A4 纵向、边距 0** ✓；图像**按页宽缩放**（保持纵横比 ✓）、**按页高分页** ✓。
  2. **px ↔ pt**：**1 px = 1 pt 只作为"放置单位"** ✓（PDF 的 72 dpi ✓），但**长图必须缩放并分页** ✗ —— 因为 **PDF 的单边上限是 14 400 pt**（≈200 英寸 ✓），而 80 882 px 的截图在 1:1 下**远超上限** ✗。
     - **自我更正（原推荐有误）** ✗：本文件早期版本写的是"1 px = 1 pt，无需 DPI 概念"✗ —— 那**只在图像能装进单页时成立** ✓。正确表述是：**1 px = 1 pt 仅适用于单页可容纳的情形；超出则按页宽缩放 + 跨页** ✓。
  3. **WebP 在 PDF 中不是选择题** ✗：**PDF 格式本身不支持 WebP** ✓，只能嵌入 **PNG/Flate（无损 ✓）或 JPEG** ✓。规则：
     - 源是 **WebP** ⇒ **一律 PNG/Flate** ✓（保持无损 ✓）；
     - 源是 **JPG** ⇒ 可直接嵌 **JPEG** ✓；
     - 源是 **PNG** ⇒ **Flate** ✓。
  4. **分页与分片是同一套机制** ✓（都按"页高 / 片高"切 ✓）⇒ S7 的两个功能**共用切分逻辑** ✓（已写进 S7 实现清单 ✓）。
- **规格需改动**：§9 删掉两条 `【待决】` ✓，补上第 2 条的更正表述 ✓。
- **影响任务段**：S7（**解除实施闸门** ✓；估时仍待细化 ✗，不给承诺值 ✓）。

### D12 取消保存面板后的行为 `[已定]`

- **规格位置**：§2.3 生命周期 —— 原规格**未写**“取消后是否回到截图框” ✗。
- **决定**：**默认退出截图** ✓（无状态残留 ✓、语义最简单 ✓）；**可配置**为“**回到截图框继续调整**” ✓ —— 此时 `PendingCapture` 必须**一直持有到面板关闭** ✓（见 §3）。
- **理由**：默认值选“最简单且没有隐性状态”的那条 ✓；需要“调整完再存”的用户可显式打开回退 ✓。
- **规格需改动**：§2.3 / §15 补一句“**取消后默认退出截图；可配置回到截图框**” ✓。
- **影响任务段**：S3（面板关闭路径 ✓）、S10（与捕获流程的衔接 ✓）。

## 3. 数据源与编码产物所有权

### 3.1 为什么需要它（P0 根因）

「保存」这个去向要求**先打开面板、后写文件**。现有导出路径是"确认 ⇒ 立刻导出 ⇒ 写文件"，中间没有"持有像素但不写盘"的形态。若为了打开面板而把滚动产物 `into_image()` 物化一次，就把 `docs/35` 刚解决的 4.0 MB 重新变成 161.9 MB。

### 3.2 所有权边界

```rust
/// capture crate 内部持有 SelectionPixels / ScrollBands / 已有 artifact；应用层只持有句柄。
pub struct PendingCapture { /* opaque, single owner */ }

/// 编码完成后的单一产物；临时文件及其删除责任由该对象唯一持有。
pub struct EncodedArtifact { /* opaque; path, size, format, dimensions, request key */ }
```

`PendingCapture`、`ScrollBands` 和源枚举都归 `snapclip-capture` 所有。app crate 不直接命名或复制 `ScrollBands`；capture crate 通过窄接口提供尺寸、格式能力检查和有界行带读取。不得在输入句柄与独立 lease 字段中重复持有同一源。

`EncodedArtifact` 是保存面板、编码 worker 与文件服务之间的传递对象。编码器直接写入临时文件；缓存只保留有界的 artifact 文件索引，不缓存整图编码 `Vec`。解码预览按可见区域/有界 tile 提供像素，S2/S4 用基准确定并测试缓存字节上限。

### 3.3 七个问题的回答

| # | 问题 | 回答 |
| --- | --- | --- |
| 1 | **像素由谁持有？** | capture crate 的 opaque `PendingCapture` 独占持有普通源、滚动 tile lease 或既有 artifact；app crate 不持有 crate-private 的 `ScrollBands`。 |
| 2 | **取消面板如何释放？** | `PendingCapture::Drop` 释放其唯一持有的输入源并清理专属临时文件；编码结果由 `EncodedArtifact::Drop` 清理。保存成功的最终文件不归临时对象所有。 |
| 3 | **普通与滚动是否都支持？** | 都支持：普通源与滚动行带源均可产生 `EncodedArtifact`。已有落盘 artifact 可作为输入源复用，不在 app 层复制像素。 |
| 4 | **滚动是否继续按带处理？** | 是。capture crate 通过公开窄接口回放有界行带；`ScrollBands` 本身保持 crate-private。PNG/JPEG 按行写入，WebP 只在格式和内存上限允许时接受，超限在读取任何行前拒绝。 |
| 5 | **预览/复制/拖出/保存是否共享同一编码结果？** | **是**。单一文件型 `EncodedArtifact` 是唯一编码产物；预览解码它，复制从它解码并发布正确的剪贴板格式，拖出使用它，保存复制其字节到目标 `.partial` 后提交。保存不重新编码。 |
| 6 | **编码取消与过时结果如何处理？** | 复用导出线程的既有协议：**容量 1 的 mailbox + 单调 generation + 过时结果丢弃**（`windows/export_worker.rs:13-16`、`:224-236`、`EXPORT_READY_MESSAGE = WM_APP + 19`）。参数变更 ⇒ 提交新代次 ⇒ 旧代次的结果到达时被丢弃，不覆盖 UI。 |
| 7 | **关闭面板后临时源如何清理？** | 见 #2。若已成功保存，只释放输入 tile 与临时 artifact（成品保留）；若用户取消，未提交的临时 artifact 和 tile 均删除。 |

### 3.4 硬性禁止

- **禁止**为了打开面板而调用 `into_image()` / `materialise()` 物化整图。PNG artifact 可直接作为注册 PNG 格式发布；`CF_DIBV5` 只在解码像素不超过预算时额外提供。不得把 JPEG/WebP 字节标成 PNG；若某格式无法在预算内提供任何可消费的剪贴板表示，应明确报告复制失败。
- **禁止**面板打开期间再复制一份像素（`Whole` 里 `SelectionPixels` 按值移动，不 clone）。
- **禁止**把长图编码结果和完整解码预览无上限地同时留在内存；缓存必须按字节计量并可驱逐。
