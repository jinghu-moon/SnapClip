Color system / v4

颜色不是装饰，
而是界面的结构语言。

先选职责，再选颜色；先保证状态可理解，再追求视觉变化。这份规范把 SnapClip 的原始色板、语义角色、组件状态和浅深色主题串成一条可执行规则。

Primitive → Semantic → Component正文 ≥ 4.5:1UI 边界 ≥ 3:1Light / Dark / System

颜色分层

组件永远从职责出发，不直接从色板挑颜色。

Primitive原始色阶--azure-600只用于生成语义角色、色板和内容层。
→
Semantic语义角色--accent-solid描述“它做什么”，不描述“它是什么色”。
→
Component组件契约--button-primary-background组件只消费稳定的视觉状态契约。

允许

background: var(--button-primary-background); color: var(--button-primary-color);

禁止

background: var(--azure-600); color: #fff;

表面层级

用 Surface、边框和 elevation 表达空间关系，不用随机颜色制造层级。

Level 0--page页面画布
Level 1--surface普通容器
Subtle--surface-subtle弱区分区域
Component--surface-component控件组
Level 2--surface-level-2Popover / Menu
Level 3--surface-level-3Dialog
Inverse--surface-inverseTooltip / Toast
关键约束浅色主题中 Level 2 和 Level 3 都是白色表面，层级不依赖填充色：两者各自绑定一个语义边框角色，即使阴影被禁用、被容器裁剪或处于高对比度模式，层级仍然可读。

边界与降级

Level 3 边框必须比 Level 2 更强，两层不能共用同一边框角色。阴影只是附加效果：禁用阴影后边框仍须成立，系统进入 forced-colors 时回退到 CanvasText。填充色本身不承担层级语义，因此允许 Level 1、Level 2、Level 3 使用相同填充值。

文本与边框

文字负责信息层级，边框负责结构边界；两者不要互相滥用。

文本角色

角色 用途 示例
--text-primary 正文、标题、主要控件 主要内容
--text-secondary 辅助说明、次要标签 辅助说明
--text-placeholder 输入占位符 请输入内容
--text-link 可点击链接 查看详情

交互状态

Hover 和 Pressed 使用组件前景色混合，Focus 独立存在，Disabled 不承担状态语义。

Default原始背景
Hoverforeground × 8%
Pressedforeground × 10%
Focus--focus-ring
Selected--selected-background
Disabled--disabled-content

强选中 vs 弱选中

Strong selection--selection-bg / --selection-fg
Soft selection--selected-background / --selected-color

不要只靠颜色

Selected 应同时使用文字、图标、marker、阴影或形状；Error、Success、Warning 也必须有文字或图标线索。

状态颜色

状态颜色成组使用：边框、背景、前景一起表达同一个语义。

Info信息、处理中、提示--info-*
Success完成、可用、已保存--success-*
Warning注意、等待、风险--warning-*
Error失败、删除、非法输入--error-*

浅色与深色

深色不是浅色的 RGB 反转；两套主题分别定义 Surface、Text、Border、Status 和 Accent。

Lightdata-theme="light"
Page#f5f5f5
Surface#ffffff
Text#1f1f1f
Border#e0e0e0
Darkdata-theme="dark"
Page#101010
Surface#181818
Text#f5f5f5
Border#383838
  • 1

    组件只引用 Semantic 或 Component Token，不在组件 CSS 中写深色临时补丁。

  • 2

    每次颜色修改都要同时检查 Light、Dark 和跟随系统三种状态。

  • 3

    Accent 只表达当前所在：当前工具、当前选区、当前 Tab、链接和 Focus。

验收清单

颜色修改完成前，必须确认视觉层级和可访问性没有回归。

  • ✓

    正文和主要控件文字达到 4.5:1。

  • ✓

    UI 边界和 Focus Ring 达到 3:1。

  • ✓

    Hover、Pressed、Selected、Disabled 在两套主题中可区分。

  • ✓

    关键状态不只依赖颜色。

Token 配对审计

64/64PASS

覆盖 32 组契约配对、浅色与深色各一次。这一项只证明 Token 配对本身：文字与控件边界对比度、状态配对、浮层文字配对。 

node tools/audit-design-tokens.mjs

可执行审计共 21 项检查：加载完整性、Cascade Layer 顺序、Token 引用可解析、组件 CSS 无 Hex、配对对比度复算、表面填充矩阵、无阴影边框契约、Level 2 / Level 3 边框不共用、forced-colors 回退、Token 导出完整性、390px 无横向溢出。

仍未覆盖的验收项

  • !

    实际 Vue 组件而非原型页面：原型只证明 Token 契约，组件接入后必须在真实组件上重跑审计。

  • !

    Windows 高对比度下的原生控件外观，以及色弱、低亮度显示器下的状态辨识。

  • !

    Mark 标注色叠加真实图片内容后的文字可读性；当前只有 Token 层面的配对结论。

已知边界浅色主题中 --page / --surface 填充对比为 1.09:1，--surface / --surface-subtle 为 1.04:1，--surface / --surface-level-2 为 1.00:1，均低于 1.10:1 的相邻表面判读门槛。因此这些角色不依赖填充色区分，而是依赖边框与 elevation 契约；审计会输出完整的表面填充矩阵，并在该矩阵发生变化时报告。
